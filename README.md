# KETEP DIPS 기후테크 뉴스레터 제작 사이트 (GitHub Pages)

**Google / GPT / 서버 계정 없이 사용 가능한 정적 웹 프로토타입.** GitHub Pages와 GitHub Actions는 소유자 GitHub 계정에서 운영하고, 직원은 사이트 URL만 열어 사용합니다.

## 기능

- 4단계: 공고 선택 → 내용 편집 → 뉴스레터 미리보기 → HTML 전체 복사 / 서식 포함 복사 / HTML 파일 저장
- 직접 공고 등록: URL만으로도 '확인 필요' 항목 생성, 기관·마감일·요약 수정 가능
- 공고 검색·유형·상태·41개 기업별 매칭 필터 (해당 기업 파일을 브라우저에 불러온 경우)
- 자동 수집: 등록된 기업마당 공식 API 키를 GitHub Actions Secrets에 넣으면 매일 08:37 KST 전후에 수집, 정적 JSON 갱신, 사이트 자동 배포
- 직접 등록 목록 내보내기/불러오기 (JSON), 선택/편집 내용 브라우저 저장
- 외부 서비스 유료 AI 호출 없음

## 1. 먼저 실행해보기

컴퓨터에 Python이 설치되어 있다면 저장소 폴더에서 다음을 실행합니다.

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000` 접속. `index.html`을 더블클릭해도 공고 직접 추가·뉴스레터 생성·복사는 동작하지만 브라우저 보안상 JSON 자동 불러오기가 제한될 수 있습니다.

실제 공고 수집을 설정하기 전에는 **[시연용]** 예시 3개를 보여 줍니다. 가상 공고를 실제 뉴스레터로 발송하면 안 됩니다.

## 2. 개인 GitHub 계정에 별도 저장소 만들기

1. GitHub에 로그인하여 새 **Public repository** 생성. 예: `ketep-dips-newsletter`. 기존 운영 중인 `KETEP_DIPS` 저장소에는 덮어쓰지 마세요.
2. 이 ZIP을 풀고 숨김 폴더 `.github`까지 전체 파일을 해당 저장소 `main` 브랜치에 업로드합니다.
3. `Settings > Pages > Build and deployment > Source: GitHub Actions`를 선택합니다.
4. `Actions > Collect notices and deploy website > Run workflow`를 한 번 실행합니다.
5. `Settings > Pages`에 표시되는 사이트 URL로 접속합니다. 일반적으로 `https://<GitHub 아이디>.github.io/ketep-dips-newsletter/` 형태입니다.

GitHub Pages는 **공개 웹사이트**입니다. 사이트에 올라간 파일은 누구나 볼 수 있으므로 개인정보/비공개 내부기업 자료를 저장소에 올리지 마세요. 저장소 이름과 주소는 사용자가 만든 이름에 따라 달라집니다.

## 3. 매일 자동 공고 수집 설정

1. 기업마당의 [지원사업정보 API](https://www.bizinfo.go.kr/apiDetail.do?id=bizinfoApi)에서 서비스 인증키 사용 신청.
2. GitHub 저장소 `Settings > Secrets and variables > Actions > New repository secret`에서 `BIZINFO_API_KEY`라는 이름으로 인증키 등록.
3. `Actions > Collect notices and deploy website > Run workflow` 수동 실행으로 테스트.
4. 오류가 없다면 하루 한 번 GitHub Actions 예약 작업이 자동 실행되고 `data/opportunities.json`이 갱신됩니다.
5. `data/opportunities.json` 안의 `source_status`, `updated_at`으로 실행 상태 확인.

**주의**: 인증키가 없으면 공고 데이터는 자동으로 수집되지 않습니다. 이 ZIP에는 인증키가 포함되어 있지 않습니다. API 응답은 변동될 수 있으므로 최초 연결 뒤 실제 API 데이터를 확인해야 합니다. 무료 플랜 제한, GitHub 예약실행 지연 또는 정책 변경 가능성이 있어 정기 점검이 필요합니다.

현재 기본 수집 대상은 기업마당 지원사업정보 API 한 곳입니다. K-Startup, 대기업 오픈이노베이션, 행사 API 등은 각 서비스별 승인키/데이터 규격 확인 후 수집 스크립트에 추가할 수 있습니다. 모든 공고를 자동 수집한다거나 중복수혜 가능성을 확정한다고 표시하지 않습니다.

## 4. 41개 기업 자료 연결

프로토타입과 별도로 제공되는 `KETEP_41개기업_로컬전용_불러오기.json` 파일은 원본 XLSX의 **기업명, 기술분야, 세부분야, 제품, 소재지, 창업연도, 선정연도**만 추출한 것입니다. 대표자, 학력 등 불필요한 개인정보는 포함하지 않았습니다.

이 파일은 **GitHub 저장소에 업로드하지 마세요.** 직원에게 사내 허용된 방법으로 별도 전달하고, 각 직원이 사이트 왼쪽의 **'41개 기업 자료 불러오기'** 버튼을 눌러 사용합니다. 정보는 각자의 브라우저 localStorage에 저장되어 페이지 새로고침 후에도 남습니다. 해당 브라우저 데이터 삭제 또는 기기 변경 시 다시 불러와야 합니다.

기업 매칭은 기술 키워드 기반의 **참고용 유사도 표시**입니다. 단순 키워드 매칭 결과이므로 지원 자격 판정이 아닙니다.

## 5. URL 직접 등록과 직원 간 공유

직원이 URL을 추가하면 해당 **기기의 해당 브라우저**에만 저장됩니다. 로그인 없는 GitHub Pages는 서버 DB에 직접 쓰지 못합니다. 타 직원과 공유하려면 **'직접 등록 공고 내보내기'**로 JSON 파일을 전달하고, 다른 직원이 **'직접 등록 공고 불러오기'**를 사용해야 합니다.

지속 공유가 필요하면 담당자가 직원에게 받은 공고를 검수한 뒤 저장소 `data/opportunities.json`에 등록하거나, 승인된 공용 백엔드를 별도로 도입해야 합니다. 브라우저에 개인 액세스 토큰을 입력하게 하거나 GitHub 키를 클라이언트 코드에 넣는 방식은 금지합니다.

URL만 입력했을 때 타 사이트 내용을 자동으로 읽어오는 기능은 이 버전에 포함되지 않았습니다. 브라우저에서 타 사이트 HTML을 직접 읽는 것은 대개 CORS 제한을 받으므로, 제목·기관·마감일·요약은 편집 단계에서 보완해야 합니다.

## 6. DIPS와 중복 수혜 검토

API의 짧은 요약에 '중복지원', '동시수행' 등의 표현이 있으면 **조건 검토 필요**로 표시합니다. 이러한 표현이 발견되지 않아도 **중복수혜 미확인**으로 표시합니다. 명시적 적격 판정이 아니므로 담당자가 원문, 공고 첨부파일, 2027년도 DIPS 사업 지침 및 실제 협약 조건을 검토해야 합니다.

## 7. 이메일 발송 안내

1. 공고 선택 및 편집 → 미리보기 확인.
2. HTML 소스를 지원하는 메일 편집기는 'HTML 소스 전체 복사'를 선택.
3. 일반 리치 텍스트 편집기는 '서식 포함 복사'를 선택. 브라우저 보안상 복사가 차단되면 'HTML 파일 저장'으로 대체.
4. 반드시 **본인에게 테스트 메일**을 발송하여 줄바꿈·링크·표 스타일·하단 면책문구를 확인.
5. 뉴스레터 생성 자체는 발송이 아닙니다. 메일 발송은 기존 사내 메일 시스템에서 진행합니다.

## 8. 구조

```text
index.html                         4단계 웹 화면
styles.css                         웹 디자인
app.js                             공고 필터·선택·편집·뉴스레터 생성
data/opportunities.json            공개 공고 목록 (초기 비어 있음)
scripts/update_opportunities.py    공식 기업마당 API 수집기
.github/workflows/update-and-deploy.yml
                                   매일 수집 + Pages 배포
tests/test_collector.py             백엔드 데이터 처리 테스트
```

## 9. 인수인계 체크리스트

- 웹사이트 주소와 GitHub 저장소 관리자 계정, 2단계 인증/복구 수단을 기관 정책에 맞게 관리
- 기업마당 API 키의 소유자, 만료/연장 절차를 기록
- GitHub Actions 마지막 성공 실행과 수집 건수 확인
- 자동수집이 멈추거나 API 형식이 변경될 경우의 담당자와 문의 창구 지정
- 41개 기업 정보 변경 시 로컬 JSON 갱신 및 담당자 배포
- `data/opportunities.json`, 수집 스크립트, 직접 등록 공고 JSON을 정기 백업
- 개인 계정에만 의존할 경우 접근권 회수·분실·서비스 변경에 따른 지속성 위험을 문서화
